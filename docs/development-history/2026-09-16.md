# KitonCLI Development History — 2026-09-16

## What Changed

- Initialized development history tracking system based on the provided instructions.
- **Removed old plugin architecture:** Deleted `src/plugins/index.ts` and the `ProjectPlugin` type. The imperative plugin approach was replaced with a new mapping system.
- **Introduced mappings system:** Created the `src/core/mappings/` directory containing `executor.ts`, `resolver.ts`, and `types.ts`. This declarative approach maps technologies to their required transformations.
- **Added AST transformations:** Set up `src/core/transformations/ast/` with `parser.ts` and `printer.ts` to manipulate source code via AST.
- **Added ts-morph dependency:** Installed `ts-morph` to handle parsing, manipulating, and printing TypeScript ASTs reliably.
- **Implemented transformation operations:** Added specific AST operations inside `src/core/transformations/operations/`: `add-import`, `add-property`, and `add-array-element`.
- **Restructured technology mappings:** Implemented `tailwind.ts` to use the new mapping system, defining its installation via AST operations rather than raw text modification.
- **Updated entry point:** Modified `src/index.ts` to iterate through and apply `mappings` instead of the old plugins.

## Decisions

- Set up the structure for daily development history to ensure continuity across sessions.
- **Switch from regex/string replacement to AST manipulation:** Decided to use `ts-morph` for configuring technologies (like Tailwind). This ensures modifications (like adding imports or updating configuration objects) are structurally safe and immune to formatting differences.
- **Declarative mappings over imperative plugins:** Moved to a mapping-driven architecture where technologies define an array of `ASTTransformation` objects, making it easier to declare what a technology needs without writing custom injection logic every time.

## Problems / Fixes

- None yet.
- **Ensuring idempotent transformations:** To prevent duplicate code when the CLI is run multiple times, transformation operations were designed to be idempotent. The operations (`add-import`, `add-property`, `add-array-element`) explicitly check if the target node or value already exists before modifying the AST.
